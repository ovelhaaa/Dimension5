# JUCE watermark / licensing note

## Observed behaviour

The UI snapshots generated by `tests/test_dimension_juce.cpp` include a
`Made with JUCE` splash overlay in the lower-right corner of the editor.

This is not drawn by Dimension5. It is created by JUCE itself in
`AudioProcessorEditor` (`juce_AudioProcessorEditor.cpp`, "SECTION A",
`new JUCESplashScreen (*this)`) for builds that do not use a JUCE Indie/Pro
licence. The local build uses the JUCE checkout referenced by
`build-plugin-local/CMakeCache.txt` with no licence configuration.

The overlay is therefore expected in development snapshots and must not be
removed, patched out or hidden by the plugin code.

## Why the UI changed

Even though the overlay is legitimate, the interface must not depend on
controls placed underneath it. The UI 2.1 layout reserves a safe strip on the
right edge of the bottom bar:

- `ADVANCED DSP` is placed to the left of the reserved strip.
- Input/output controls and meters remain outside the overlay area.
- The advanced drawer keeps its interactive controls away from the lower-right
  corner.

## Legitimate removal for a distributed product

The JUCE EULA allows the splash overlay to be suppressed through the official
licensing route, for example:

1. Acquire a valid JUCE Indie or Pro licence from Raw Material Software and
   configure that licence in the build environment according to the JUCE
   documentation; or
2. Distribute the product in compliance with the applicable JUCE open-source
   licence terms.

Do not modify JUCE's `SECTION A`, monkey-patch the editor, or use window masks
to hide the overlay. The correct procedure is a licensing/build configuration
change, not a UI workaround.

The same rules apply to CI-produced release builds: a release artefact must be
built with the licence configuration that covers its distribution model.
